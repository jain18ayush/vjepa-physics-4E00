Orientation

Two papers, one confusion

You already saw experiment writeups. This deck ignores the numbers until you own the pictures. The whole project is three nested ideas.

1. A probe

A linear “lie detector.” Given an activation vector, output a number (or an angle). Good when the property is linearly readable.

2. A curve

Where activations sit as the property changes continuously. Steering should walk that curve, not cut across it.

3. A tube

The curve is only a spine. Real activations form a thick neighborhood around it. Thickness is not the same as “more probe directions.”

Part 1 of the take-home is Joseph et al.: find probes for speed, acceleration, and direction in V-JEPA. Part 2 is Goodfire: fit a curve through concept averages and ask whether steering should follow it. The “tube” is what you get when both stories are partly true.

Part 1 · idea 1

An activation is a point in a big space

V-JEPA’s encoder turns a short video into vectors. After each transformer block you get a list of tokens. We average them into one vector of length 1024.

So every clip, at every layer, is a single point in 1024-dimensional space. Speed, acceleration, and direction are properties of the clip. The research question is: which properties can you read off that point with a simple linear map?

prediction = W · h + b

h is the 1024-vector. W is a matrix of weights the probe learns. For speed, the prediction is one number. For direction, it is a pair (sin θ, cos θ) so the circle has no awkward cut at 0°/360°.

Nothing here trains the video model. The encoder stays frozen. Only the tiny probe is trained.

Dots are toy activations colored by direction. Early layers: colors mixed. Later: colors separate along a loop. This is a cartoon of “becoming linearly readable,” not the real 1024-D data.

Part 1 · idea 2

A probe is a lie detector, not a map of the space

Think of the classic linear “lie detector” in interpretability: train a classifier on activations to detect a property (truthful vs lying, male vs female names, toxic vs clean). If it works, the property is linearly readable.

That is a statement about a function of the activation:

score = w · h

Geometrically, w is one arrow. The probe says: “project the point onto this arrow; the number you get is the property.” Everything perpendicular to w is invisible to that probe.

So a great probe does not tell you:

  • whether activations for different values form a line, a circle, or a cloud,
  • whether other properties are mixed into the leftover directions,
  • how to move from “slow” to “fast” without breaking other things.

It only tells you: I can read this property with a linear score.

0.00probe score = w · h

Blue arrow is the probe direction. Drag the point. The score only cares about the projection onto the arrow. Sliding along the dashed line (perpendicular to w) does not change the score at all.

Derive it · scripts/common.py + metrics.py

A probe is literally nn.Linear(1024, n_out) trained with MSE. Direction targets are sine/cosine, not the raw angle.

# targets
y = theta_to_sincos(theta_degrees)   # (N, 2) = [sin θ, cos θ]
# or for speed/accel: y = magnitude[:, None]

probe = nn.Linear(1024, y.shape[1])  # bias trained; not part of subspace later
opt = torch.optim.Adam(probe.parameters(), lr=1e-3, weight_decay=1e-4)
for _ in range(epochs):
    pred = probe(X)
    loss = ((pred - y) ** 2).mean()
    loss.backward(); opt.step()

# read angle back
pred_deg = degrees(atan2(pred[:, 0], pred[:, 1])) % 360
err = ((pred_deg - true_deg + 180) % 360) - 180   # circular MAE

Part 1 · experiment A

Ask the probe at every layer

Train one probe per layer. Plot how well it reads each property. That answers: when does the property become available?

On this project’s blue-disk videos:

  • Speed and acceleration magnitude are already readable at layer 0.
  • Direction is weak early and jumps around layer 5.

Joseph et al. saw the same ordering on more complex videos, with the direction jump near layer 8. The ordering is the scientific claim. Exact layer numbers move with the dataset.

They call the direction jump the Physics Emergence Zone. After that, every steering experiment in this project uses the chosen layer (here: 5).

Part 1 · experiment B

Delete the probe. Is the property still there?

One probe direction might be enough. Or the network might store the same property many times along different axes.

Iterative nullspace probing:

  1. Fit a probe.
  2. Project its direction(s) out of every activation (set that component to zero).
  3. Fit a new probe on what is left.
  4. Repeat until the probe fails.

If it fails after 1–2 rounds, the property was low-dimensional. If it keeps succeeding for dozens of rounds, the property is stored redundantly across many orthogonal directions.

In this project: direction kept working for ~41 probes (82 dimensions, because each direction probe removes up to 2 axes). Speed died after ~5. Acceleration after ~2.

That is still a probe story: “how many independent lie detectors can I train in a row?” It is not yet a story about curves.

Derive it · scripts/nullspace.py + common.project_out

Fit, score, QR the weight, subtract that subspace from X, repeat. The probe that crosses the stop rule is not kept.

def project_out(X, weight):           # weight: (n_out, 1024)
    Q, R = np.linalg.qr(weight.T, mode="reduced")
    Q = Q[:, np.abs(np.diag(R)) >= 1e-6]
    return X - X @ Q @ Q.T            # remove those columns from every row

X_tr, X_va = X[train].copy(), X[val].copy()
kept = []
for k in range(max_iters):
    probe = train_probe_c11(X_tr, y_tr, kind=kind, device=device)
    metrics = score_probe(probe, X_va, y_va, kind=kind)
    if should_stop(kind, metrics):    # dir: R²<0.1 or MAE>80°
        break
    kept.append(probe)
    X_tr = project_out(X_tr, probe.weight)
    X_va = project_out(X_va, probe.weight)

dim = 2 * len(kept) if kind == "direction" else len(kept)

Part 1 · experiment C

Steering: edit the activation, then ask a second probe

Open the step-by-step steering visual →

Correlation is not control. To test control:

  1. Build a subspace from the training probes (the nullspace sequence).
  2. On a held-out clip, replace the coordinates inside that subspace so the training probes all output a target angle (here: 90°).
  3. Leave everything orthogonal to the subspace alone.
  4. Read the edited vector with a new probe that never saw the edit.
x* = V c* + (x − V Vᵀ x)

One probe barely moves the decoded angle. Many coordinated probes do. Error to 90° falls; error to the clip’s true angle rises. That opposing pair is the causal signature.

Still a subspace story: “move along several probe axes at once.” We have not drawn a curve.

19°error to true angle

Derive it · scripts/steer.py

Build orthonormal V from the first n probe weights. Replace coordinates inside V so every included probe outputs (sin θ*, cos θ*). Score with a probe fit only on unsteered test.

def steer(x, probes_n, theta_star_rad):
    M = torch.cat([p.weight.T for p in probes_n], dim=1)  # (1024, 2n)
    V, _ = torch.linalg.qr(M, mode="reduced")
    x_perp = x - V @ (V.T @ x)          # leave orthogonal complement
    t = tensor([sin(θ*), cos(θ*)])
    rows, rhs = [], []
    for p in probes_n:
        rows.append(p.weight @ V)       # (2, rank)
        rhs.append(t - p.bias - p.weight @ x_perp)
    c_star = lstsq(cat(rows), cat(rhs)).solution
    return V @ c_star + x_perp          # x*

# Evaluation probe: fit on unsteered test ONLY, then freeze
eval_probe = train_probe_c11(X_test, sincos(y_test), kind="direction")
for n in [1, 5, 10, 20, 41]:
    X_star = stack([steer(x, probes[:n], π/2) for x in X_test])
    mae_to_90 = circular_mae(eval_probe(X_star), 90°)
    mae_to_truth = circular_mae(eval_probe(X_star), y_test)
Bridge

What Part 1 cannot see

Part 1 answers: readable? how many axes? editable with those axes? It does not answer: what shape do the activations form as the label changes?

Probe / subspace picture

Property = linear score(s). Geometry = a stack of arrows. Intervention = slide along those arrows.

Manifold picture

Property = position along a curve of average activations. Geometry = the curve. Intervention = walk the curve.

Why you need both

A circle needs many linear probes to cover sine and cosine copies. A subspace edit does not tell you that walking halfway should pass through 90°.

Part 2 imports Goodfire’s manifold steering to ask the shape question on the same activations.

Part 2 · idea 1

Centroids, then a spline

Group every training clip by its label (each of 64 angles, or each speed). Average the activations in a group. That average is a centroid.

Connect the centroids in label order with a smooth curve (a cubic spline). For direction, the order is circular, so the spline is periodic: 0° meets 360°.

This curve is not discovered by an unsupervised manifold algorithm. You already know the ordering from the labels. The spline is just the smoothest path through the averages.

Goodfire’s claim: if you want to change the concept from A to B, move along this curve. Do not take the straight line between A and B.

Black dots = centroids (one per angle). Teal = spline through them. Drag “cloud” to fade in individual activations around each centroid — foreshadowing the tube.

Derive it · scripts/part2_splines.py · fit_spline

PCA on train → average per label → cubic spline in that subspace. Direction uses a periodic boundary so 0° meets 360°.

pca = PCA(n_components=64).fit(X_train)
Z = pca.transform(X_train)

centroids, labels = [], []
for lab in np.unique(y_train):
    centroids.append(Z[y_train == lab].mean(axis=0))
    labels.append(lab)
centroids = np.stack(centroids)

if kind == "direction":
    u = (labels % 360) / 360.0
    # periodic: append first point at u=1 so the spline closes
    u_fit = np.r_[u, 1.0]
    c_fit = np.vstack([centroids, centroids[0]])
    spline = CubicSpline(u_fit, c_fit, axis=0, bc_type="periodic")
else:
    u = (labels - labels.min()) / (labels.max() - labels.min())
    spline = CubicSpline(u, centroids, axis=0, bc_type="natural")

# Steering later: replace only the PCA block; keep leftover
leftover = X - pca.inverse_transform(pca.transform(X))

Part 2 · idea 2

Chord vs curve: the middle is the test

Both paths share endpoints. Only the middle differs.

chord: (1−t)·h₀ + t·h₁
spline: s( (1−t)·u₀ + t·u₁ )

On a half-turn of the direction circle, the chord cuts through the interior. Midway you are not “at 90°.” You are at a mixture of 0° and 180° — or something the probe does not treat as an angle at all.

On this project’s data, mid-path error to the claimed angle was about 5° on the spline and about 171° on the chord. Endpoints match by construction.

For speed (a nearly flat variable), spline and chord almost agree. Curvature only matters when the concept is curved.

90°decoded angle (toy probe on the circle)

Toy 2D circle. On the chord at t=0.5 the “decoded angle” becomes meaningless / jumps. On the spline it passes through 90°.

Derive it · path construction in part2_splines.py

Both paths live in the same 64-D PCA block. Only the interpolation differs. Score every waypoint with a frozen eval probe.

ts = np.linspace(0, 1, 21)
u_t = circular_lerp(u0, u1, ts)          # shorter arc on the circle

The confusion you named

Tube ≠ “the linear splits probes learn”

A probe finds a direction to project onto (a lie-detector axis). Many orthogonal probes find many such axes. That is a subspace.

A tube is a claim about where the points live:

  • There is a thin spine (the circle of angles).
  • For one fixed angle, activations are not one point. They form a blob around that point on the spine.
  • Moving along the spine changes the angle.
  • Moving inside the blob (perpendicular to the spine) mostly keeps the same angle.

So:

  • Probe subspace = which directions you are allowed to edit to change the score.
  • Tube = the solid neighborhood of activations around the concept curve.

They can overlap. Part 1’s many probes often point somewhere inside the tube. But “82 probe dimensions” is not the definition of a tube. The tube is the cloud. The probes are rulers you hold up to the cloud.

—decoded angle

Amber ring = tube. Teal = spine. Moving on the spine changes θ. Moving in the fiber (across the ring) mostly does not.

Derive it · scripts/part2_tube.py · fit_tube_basis

Find nearest spine point, strip the tangent, PCA the leftover. Those PCs are the tube axes — not the same object as probe.weight.

Z = pca.transform(X_fit)
u*, z*, T, _ = nearest_on_spline(Z, spline)   # T = unit tangent s'(u*)
r = Z - z*
r_perp = r - (r · T)[:, None] * T             # remove along-spine part

# Tube basis = principal directions of the perpendicular cloud
U, S, Vt = np.linalg.svd(r_perp - r_perp.mean(0), full_matrices=False)
V_k = Vt[:k].T                                # (n_pca, k) normal coords

# Steer: stay on spine, add a little tube to hit the probe target
z(t) = s(u(t)) + t * (V_k @ c*)               # c* from lstsq like Part 1
# k=0 → spline only; k=2 ≈ multi-probe n=20 at the endpoint
What fills the tube?

Same angle, different reasons to be off-spine

Fiber

Many activations decode as the same θ. The probe score is flat across this slice. Like sliding perpendicular to w on the lie-detector slide — score unchanged.

Nuisance

Other properties live in the leftover directions. On these disks, speed is strongly readable from the tube directions, not from the angle spine.

Copies

Extra directions that still correlate with angle — Part 1’s redundant probes. They sit in the tubular neighborhood, but they are not always the same as “largest leftover variance” (which is often speed).

That is why the writeups sound like they are contradicting themselves: direction is “1D” (you can walk a circle) and “high-D” (you need many probes / the cloud is thick). Both: 1D spine, thick neighborhood.

Practical recipe this project landed on

Walk the circle when you care about intermediate angles. Add ~2 directions in the tube when you need to nail a hard endpoint. That matches multi-probe’s endpoint accuracy without recreating the chord’s mid-path teleport.

What you should be able to say out loud

  • A probe is a linear lie detector: it projects activations onto one (or a few) directions.
  • High probe dimensionality means many redundant detectors still work after you delete previous ones. It does not by itself mean “the concept is a tube.”
  • A manifold / spline is the path of average activations as the label changes. Steering mid-path should follow it when the concept is curved.
  • A tube means those averages are a spine, and real points form a thick neighborhood. Moving in the thickness can keep the concept fixed while changing something else (or nothing the probe cares about).
  • Direction in this project: curved spine + thick tube. Speed / acceleration: flat enough that a chord is fine.
