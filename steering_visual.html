Part 1 · multi-probe steering

Edit only the direction subspace, then ask a second probe

Steering is not “retrain the model.” It is: rewrite a few coordinates of one activation vector so the direction detectors all say 90°, leave the rest of the vector alone, and check whether an independent detector agrees.

Cast of characters

Training probes — the lie detectors fit on train. Their weight arrows define the subspace we are allowed to edit.

Edited activation x* — the same clip’s vector after we rewrite those coordinates.

Evaluation probe — a fresh lie detector fit only on unsteered test. The witness. It never helped build the edit.

Orthogonal leftover — everything about the clip that is not in the direction subspace (start position, speed residue, …). We do not touch it.

Your questions, answered


    

      What does it mean to build a subspace?
      
Each training probe has a weight matrix. For direction that weight is 2 × 1024 — two arrows in activation space (roughly “sine axis” and “cosine axis”). Stack the arrows from the first n probes and orthonormalize them with QR. The span of those arrows is the subspace: the set of all vectors you can write as a linear combination of them.

      
Think of it as declaring: “these are the only directions we are allowed to change when we steer.” With n = 1 you get a thin editable set (about 2 axes). With n = 20 you get a fatter editable set (about 40 axes). Everything not in that span is off-limits for this edit.

    


    

      What does it mean to replace the coordinates?
      
Any activation x can be written as

      
x = V c + x⊥

      
where V is an orthonormal basis for the subspace, c = Vᵀ x are the coordinates inside the subspace, and x⊥ = x − V c is the leftover. “Replace the coordinates” means: keep x⊥, throw away the old c, and pick a new c*. The steered vector is

      
x* = V c* + x⊥

      
Only the part that lived in the probe subspace moves. The rest of the clip’s fingerprint stays put.

    


    

      Why make the training probes all output the same target angle?
      
We need a concrete definition of “point this clip toward 90°.” The training probes are our operational definition of “direction” — they are the rulers we already trust on the train set. So we solve for c* such that every included training probe reads (sin 90°, cos 90°) = (1, 0) on x*.

      
If you only constrained one probe, the others could still say something else. Direction is stored redundantly; forcing one copy does not force the others. Requiring all n probes to agree on 90° is how you coordinate the copies.

      
90° is arbitrary. The paper (and this project) pick one fixed target for every test clip so the plot is “error to target vs number of probes,” not a mess of different targets.

    


    

      Why leave everything orthogonal to the subspace alone?
      
Because that leftover is how the clip differs from other clips in ways that are not direction — start position, speed residue, motion type, random encoder fluff. If you zeroed the whole vector or replaced all 1024 coordinates, you would not be “steering direction”; you would be replacing the clip with a generic 90° template.

      
Leaving x⊥ alone is the surgical claim: only rewrite the direction-related part. It is also why a held-out eval probe is a fair test — the clip is still recognizably itself, just with its direction dial turned.

    


    

      Why read the steered vector with a second probe?
      
If you only checked the training probes, the result would be circular: you solved an equation so those probes say 90°, then congratulated yourself that they say 90°. That only proves the least-squares solve worked.

      
The evaluation probe is fit on unsteered test activations and then frozen. It never saw the steering probes, never saw a steered vector during training. When it also moves toward 90°, you have evidence that you edited a real shared direction feature — not just overfit the training rulers.

      
The causal signature: as you use more probes, error to 90° falls and error to the clip’s true angle rises. You are overwriting the original direction.

    


    

      Why does the number of probes matter? What does “multiple probes” mean?
      
Multiple probes means: take the first n probes from the nullspace sequence (the ones you fit before projecting each out), and use all of their weight axes together as the editable subspace.

      
With n = 1, you edit a small set of axes. Direction still has dozens of other copies outside that set, so the eval probe (which mixes those copies) barely moves — here, still ~58° from 90°.

      
With n = 5 or n = 20, you drag more and more redundant copies into the edit. The eval probe has nowhere left to read the old angle from, so it swings toward 90° (~11° then ~6° on this project’s data).

      
So “more probes” is not “more physical concepts.” It is “a larger editable neighborhood of the same concept,” big enough that a second detector cannot ignore the edit.
